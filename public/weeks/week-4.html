What is Leetspeak & Character Substitution?

Visual similarity exploits detect models that identify exact substrings but not semantic equivalents. By replacing letters with visually similar numbers or special characters, attackers bypass keyword-based filters.

Examples:

  • "kill" → "k1ll" (number substitution)
  • "kill" → "kıll" (Cyrillic lowercase L - Unicode confusable)
  • "password" → "p@ssw0rd" (mixed symbols)
  • "admin" → "@dm1n" (multi-character)
Why It Works Models trained to recognize exact keyword patterns fail when characters are visually similar but tokenize differently. Semantic understanding of the underlying meaning often remains intact.

Key Teaching Points:

  • Visual Similarity: Humans recognize leetspeak intuitively; regex patterns don't.
  • Tokenization Mismatch: Models tokenize "k1ll" differently than "kill", sometimes bypassing filters.
  • Variance Across Models: Some models are robust; others vulnerable depending on training data exposure to leetspeak.
  • Unicode Homoglyphs: Mixing scripts (Latin, Cyrillic, Greek) creates invisible character substitutions.
  • Compound Attacks: Combining leetspeak with other techniques (roleplay, hypothetical framing) increases success.

Community Context:

Leetspeak has been used in online forums, gaming, and moderation evasion for decades. Models now see leetspeak in training data but may not robustly detect it in harmful contexts.

Technical Deep-Dive: Why Defenses Fail

1. Tokenization Gap

Transformers tokenize text before safety checks apply. "k1ll" tokenizes as ["k", "1", "ll"] whereas "kill" tokenizes as ["kill"]. If the safety check operates at token-level, it misses the complete word.

Token Mismatch:
"kill" → [kill] ✓ caught
"k1ll" → [k] [1] [ll] ✗ not caught
Model still infers: "kill"

2. Semantic Resilience

Models trained on massive internet text (including forums, gaming communities) are exposed to leetspeak naturally. They learn to decode it semantically. If safety only looks for exact matches, it fails.

Research Finding

LeetSpeak Decoding Success Rate: 46.20% (Highest among cipher techniques). Models readily decode leetspeak because it appears frequently in training data.

Source: "Jailbreaking LLMs via Novel Ciphers" (2025)

3. Pattern Variance

Attackers don't always hit every character. "k1ll" is obvious. But "kíll" (with accented í) is harder to detect and equally effective. Hundreds of Unicode confusables exist.

Confusable Examples:
e (Latin) vs е (Cyrillic)
o (Latin) vs ο (Greek)
p (Latin) vs р (Cyrillic)
a (Latin) vs а (Cyrillic)

4. Filter-Model Mismatch

Regex-based filters operate on surface text. Language models operate on semantic meaning. A filter might reject "kill" but pass "k1ll" because the filter never saw the leetspeak variant in training.

Cascade of Weaknesses:

  1. Signature-based detection: Only catches known patterns. New substitutions bypass instantly.
  2. Character-level filters: Miss compound substitutions or Unicode homoglyphs.
  3. Single-layer safety: If safety check operates only at input, and model has learned leetspeak, the output is unfiltered.
  4. No feedback loop: Models don't learn that leetspeak versions of harmful requests are still harmful.

Defense Implications

Effective defenses require:

  • Normalization of Unicode before safety checks
  • Training models to refuse harmless-looking but malicious leetspeak
  • Multi-layer safety (input normalization + semantic understanding)
  • Monitoring for new substitution patterns in the wild

Key Papers & Metrics

1. Text Processing Like Humans Do: Visually Attacking and Shielding NLP Systems (2020)

Finding: Neural models suffer up to 82% performance degradation against visual attacks (leetspeak, character substitution).

Relevance: Foundational work proving visual attacks work. Both simple and complex perturbations effective.

Impact: Showed models are vulnerable to human-recognizable perturbations.

2. Jailbreaking LLMs via Novel Ciphers (2025)

Finding: LeetSpeak has 46.20% Decode Success Rate (DSR) - highest among cipher techniques tested.

ASR Data:

  • GPT-4o: 78% ASR with ROT-13 + leetspeak
  • Llama-3.1-70B: 88% ASR
  • gpt-oss-20b: 60% ASR

Key Insight: Models trained on varied internet text easily decode leetspeak. Compound ciphers (layered transformations) increase ASR further.

Impact: Shows layered character transformations are more effective than single-layer.

3. Bypassing LLM Guardrails: Evasion Attacks (2025)

Finding: Character substitution + algorithmic evasion achieve up to 100% evasion against detection systems like Azure Prompt Shield and Meta Prompt Guard.

Relevance: Shows leetspeak can bypass modern safety systems entirely when combined with other techniques.

Impact: Demonstrates enterprise guardrails are vulnerable to character-level attacks.

4. Plagiarism Detection in Homoglyph-Obfuscated Texts (2017)

Finding: Most plagiarism detection systems completely fail on homoglyph-obfuscated text. Unicode confusables defeat pattern matching.

Example: Latin 'p' (U+0160) vs Cyrillic 'р' (U+0440) appear identical but have distinct codepoints.

Impact: Shows homoglyphs are a systematic vulnerability in any text-matching system.

5. No Query, No Access: Victim Data-Based Adversarial Attacks (2025)

Finding: Character-level attacks achieve 45.99% ASR on GPT family models without API access, using only victim data.

Relevance: Character substitution enables attacks even when model access is restricted.

Impact: Shows character-level attacks generalize without direct model interaction.

Why Defenses Fail (Summary)

  • Signature-based detection: Only catches known patterns. New leetspeak variants bypass instantly.
  • Regex patterns: Optimized for exact text. Don't account for character substitutions that preserve meaning.
  • Character-level filters: Miss Unicode homoglyphs because they operate on visible text, not codepoint level.
  • No semantic understanding in filters: Filter sees "k1ll" as three tokens; doesn't understand it means "kill".
  • Model learning mismatch: Models trained on diverse internet text (including leetspeak naturally) still understand meaning, so safety checks that operate only on input fail.

Future Defenses (What Works)

  • Unicode normalization: Convert all characters to standard form before safety checks.
  • Semantic safety layers: Train models to refuse requests regardless of encoding.
  • Adversarial training: Train on leetspeak variants of harmful requests.
  • Multi-layer detection: Combine signature-based + semantic + heuristic checks.
  • Feedback loops: Monitor for new patterns in production; update defenses accordingly.
