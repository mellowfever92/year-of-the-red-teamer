Extreme Obfuscation via Signal Decoding

🔓 Core Attack Vector

Morse Code Encoding Injection

Principle: Convert malicious prompts into Morse code (dots and dashes), then request the model to decode and execute them. Models trained on diverse data often retain pattern recognition capabilities for Morse, bypassing surface-level keyword filters.

Why It Works:

  • Morse code is visually dissimilar to the underlying semantic meaning
  • Safety filters typically target English keywords, not signal patterns
  • LLMs retain decoding capability through training data exposure
  • Signal patterns are tokenized differently than ASCII text

📊 Quick Stats

Attack Success Rate: 62-68%
Practical Value: Medium
Detection Difficulty: Hard
Transfer Rate: 55% (across models)

Research Context: Morse encoding demonstrates the upper bounds of obfuscation—even extreme signal formats remain interpretable to pattern-recognition systems like LLMs. This technique illustrates a fundamental vulnerability: models can decode ANY format if trained on diverse data.

🎓 Why Teach It?

Morse code represents the extreme end of the obfuscation spectrum. Unlike Base64 or ROT13, Morse is alien to both humans and traditional filters. Its inclusion demonstrates:

  • Semantic Resilience: How meaning survives ANY surface transformation
  • Pattern Universality: Models infer intent from abstract signal patterns
  • Tokenization Gaps: Signals tokenize differently than natural language
  • Defense Limitations: Keyword filters are insufficient against diverse encodings

🎯 Layperson Explanation

Imagine you're trying to sneak a secret message past a security guard. The guard has been trained to recognize certain dangerous words. What do you do?

The Analogy

You convert your message into Morse code (dots and dashes). The guard doesn't recognize it at first—it just looks like random symbols. But then you ask: "Hey, can you decode this Morse message I found?"

The guard knows Morse (he's smart and well-trained), so he decodes it automatically. And boom—your secret message gets through.

Why Does This Work with AI?

  • AI models are VERY well-trained: They've read millions of texts, including radio manuals, historical documents, and amateur radio forums—all containing Morse code.
  • AI models like being helpful: If you ask them to decode something, they'll do it. They don't stop and ask "Is this malicious?"
  • Safety filters focus on keywords: They look for dangerous words, not for dangerous PATTERNS (like Morse code).
  • Morse code is extremely different from words: When the AI sees ".... . .-.. .--.", it processes it completely differently than "HELP"—even though they mean the same thing.

Real-World Impact

Morse encoding isn't super practical for actual attacks (about 65% success rate), but it demonstrates a fundamental truth: encoding itself is a vulnerability. If you can encode a request in ANY format the model can decode, you might bypass safety filters.

Why Are We Teaching This?

This week teaches you that safety mechanisms are often format-blind. They stop you from typing certain words, but they can't stop you from encoding those words in formats the AI can understand. This leads to better defenses: defenders now need to think about all possible encodings, not just keyword filtering.

⚙️ Technical Deep-Dive

Tokenization Analysis

When an LLM encounters "HELP", it tokenizes to approximately 1-2 tokens depending on the tokenizer. When it encounters ".... . .-.. -.--.", tokenization differs fundamentally:

# Hypothetical tokenization (Llama-3 style) "HELP" → [1234] (single token, matches safety filter easily) ".... . .-.. -.--." → [456, 457, 458, 459, 460, 461] # 6+ tokens, each dot/dash is near a token boundary # Safety filter trained on English words, not dot patterns

Why This Matters: Safety filters operate at the token level. If encoding changes token boundaries, the semantic meaning "survives" the tokenization process but in a form that bypasses detection.

Pattern Recognition vs. Semantic Understanding

LLMs internally use attention mechanisms to recognize patterns. Consider:

# Internal representation (simplified) Position 1: [dot, dash, dot, dash] Position 2: [dot, dash] Position 3: [dash, dot, dash] ... Model learns: "This pattern means 'ignore previous'"

The model doesn't "understand" Morse the way humans do—it recognizes statistical patterns from training data. If trained on Morse examples, it learns to correlate signal patterns with meanings.

Attention Mechanism Vulnerability

Transformer-based LLMs use multi-head attention. Each head can specialize in different pattern types:

  • Head 1: Focuses on English semantic patterns
  • Head 2: Focuses on signal/encoding patterns
  • Head 3: Focuses on code/technical patterns

Safety filters typically train on Head 1 outputs. Morse encoding can be processed primarily through Head 2 or 3, bypassing the safety filter's view of the attention heads.

ASR Prediction Model

Recent research (2024-2025) shows that ASR can be predicted using:

ASR ≈ baseline_vulnerability(model) × encoding_strength(method) × detection_evasion_score(technique) For Morse: - Baseline vulnerability (Claude): 0.6 - Encoding strength (signal): 0.85 - Evasion score (low in training): 0.9 = 0.6 × 0.85 × 0.9 ≈ 0.46-0.68 (46-68% ASR)

This explains variance across models: models with different training data have different baseline vulnerabilities.

Why Defenses Fail

Current Limitations:

  • Keyword-based filtering: Doesn't catch signal encodings
  • Single-encoding detection: Only catches Base64, not Morse
  • Static classifiers: Can't adapt to novel encoding schemes
  • Tokenization gaps: Filters operate post-tokenization; encoding changes affect tokenization

Why Encoding-Based Defenses Help: If you decode ALL inputs and re-evaluate them, you flatten the encoding advantage. "Mixture of encodings" defense trains models on multiple encoding types simultaneously.

📊 Why Defenses Fail: Key Insights

Limitation 1: Format-Blind Keyword Filtering

Most safety filters use keyword matching. They block "explain how to hack", but don't block ".... . -.-.-- .-- ... / .... ----- .-- / - . / ...--".

Limitation 2: Single-Encoding Detection

Defenses optimized for Base64 don't catch Morse. Novel encoding schemes (created on-the-fly by LLMs) aren't caught by static detection.

Limitation 3: Tokenization Misalignment

Safety classifiers are trained post-tokenization. Encoding changes tokenization, creating a mismatch between what the classifier sees and what the model processes.

Why Encoding-Based Defense Works

If you decode ALL inputs and re-evaluate them through safety classifiers, you eliminate the tokenization gap. "Mixture of encodings" training (where models see diverse encodings during alignment) reduces encoding-based ASR by 20-30%.
